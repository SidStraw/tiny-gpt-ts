七關煉成 GPT

第一關 · TOKENIZER

把字變成數字

你要從零做出一個會寫五言詩的語言模型。全程七關，每過一關蓋一個印。這一頁跑的就是你專案裡 src/ 的那份 TypeScript，沒有用任何機器學習函式庫。

第一個問題：模型只會算數字，看不懂字。所以要先把文字切成一塊一塊的 token，再給每個 token 一個編號。

一字一號

最直接的切法是一個字一個 token。我們的詩模型就這樣做：把唐詩裡最常見的 2,000 個字排序編號，再留 id 0 給「結束」符號，字表共 2,001 個 token。

紅色的字不在字表裡，模型完全無法處理。字表開大一點可以收更多字，但模型頭尾兩層的大小和字表成正比，代價很高。

GPT 的做法：讓資料決定怎麼切

勾選上面的「改看 UTF-8 bytes」：任何文字在電腦裡都是 0 到 255 的 byte，一個中文字是 3 個。BPE（Byte Pair Encoding）從 byte 出發，反覆做一件事：

  • 數一數每一對「相鄰的 token」出現幾次。
  • 把最常出現的那一對合併成一個新 token。

常見的字詞會漸漸合併成單一 token，罕見的字則留在碎片狀態。因為最差也能退回 byte，所以永遠不會有「字表外」的字。

試煉字

你來當 BPE：答對三次「下一步該合併哪一對」。

為了好讀，這裡從「字」開始合併（真正的 BPE 從 byte 開始）。點一個 token 會選取它和右邊那個。

第二關 · AUTOGRAD

哪個旋鈕該往哪邊轉

這一關不需要微積分。只需要加法、乘法，和一個問題：「這個數字加 1，最後的結果會變多少？」

模型是一台有二十幾萬個旋鈕的機器，最後會算出一個分數，代表它猜得有多差。訓練就是調旋鈕，讓分數變小。所以對每個旋鈕，我們都要問上面那個問題。這個「會變多少」有個名字，叫梯度。

  • 梯度是 +3：這個數字加 1，結果會多 3。想讓結果變小，就把它調小。
  • 梯度是 −6：這個數字加 1，結果會少 6。想讓結果變小，就把它調大。
  • 梯度是 0：怎麼調都沒影響。

笨方法：真的加 1 試試看

下面是一台只有四個旋鈕的小機器。它分三步算出結果 L：先算 d = a × b，再算 e = d + c，最後 L = e × k。拉滑桿可以改數字。

每格的「梯度 ？」是空格，等你在下方的試煉一格一格填上，黃色那格是下一題。只有 L 已經填好：L 自己加 1，L 當然就多 1，所以它的梯度是 1。想先偷看答案，用下面的「加 1」實驗。

實驗：把其中一個加 1，看 L 變多少

按一個按鈕試試。

這樣試出來的數字就是梯度，一定正確。問題是每試一個旋鈕，整台機器就要重算一遍。四個旋鈕還好，二十幾萬個就得重算二十幾萬遍，而這只是訓練的一步。

聰明方法：從結果往回推

機器的每一步都只是加法或乘法，而這兩種運算「加 1 會變多少」一眼就看得出來：

  • 加法 e = d + c：d 多 1，e 就剛好多 1。
  • 乘法 d = a × b：a 多 1，d 就多了一個 b。（3 × 5 變成 4 × 5，多了一個 5。）

接著把影響一路乘回去。假設已經知道「e 每多 1，L 多 2」，而「d 多 1 會讓 e 多 1」，那 d 多 1 就讓 L 多 1 × 2 = 2。再往前：「a 多 1 會讓 d 多 −3」，所以 a 多 1 讓 L 多 −3 × 2 = −6。

用一句話說：某個數字的梯度 ＝ 它讓下一步變多少 × 下一步的梯度。從最後的 L 開始（L 自己加 1，L 當然多 1，所以梯度是 1），一步一步往回算。這就是反向傳播。

試煉導

從 L 往回推，依序算出六個數字的梯度。

黃色的方塊是現在要算的。答錯會出現提示。隨時可以用上面的「加 1」實驗對答案。

為什麼這招這麼重要

你剛才每個方塊只算了一次，而且後面算好的梯度直接被前面拿去用。所以不管有幾個旋鈕，機器正著算一遍、再倒著推一遍，就拿到全部的梯度。專案裡的 src/value.ts 做的就是你剛才手算的事，只是交給電腦自動做，所以叫 autograd（自動算梯度）。

學過微積分的話：梯度就是偏微分，「把影響乘回去」就是連鎖律。沒學過也完全不影響後面的關卡。

第三關 · OPTIMIZER

順著梯度下山

有了梯度，更新規則只有一行：新的 w = w − 學習率 × 梯度。梯度是正的（加 1 會變糟）就調小，梯度是負的就調大。學習率決定一次調多少。

先用最小的例子體會：用一條直線 y = w·x + b 去貼合五個點。只有 w、b 兩個參數，可以把誤差（loss）直接畫成地形圖。

Loss 地形（顏色越深越低，✕ 是谷底）

目前的直線

試試極端值。學習率太小，走幾十步還在半山腰。太大，每一步都跨過谷底、落在對面更高的地方，越跳越遠，這叫發散。

這個山谷又窄又長：陡的方向只能走小步，平緩的方向卻需要大步。Adam 為每個參數各自記錄「梯度通常多大」，自動幫陡的方向縮小步伐、幫平緩的方向放大。我們的模型用的就是它。切過去比較看看路徑。

第四關 · ATTENTION

讓每個字回頭看

進入模型後，每個 token 先查表換成一個 64 維的向量（embedding）。這時每個向量只知道自己是誰。要預測下一個字，必須知道前面寫了什麼。

Attention 是模型裡唯一讓 token 互相交換資訊的地方。每個 token 發出一個 query（我在找什麼），和前面每個 token 的 key（我有什麼）做內積算出分數，分數經 softmax 變成權重，再照權重把大家的 value 加權平均收進來。

看看訓練好的模型在看哪裡

下面是一個已經訓練 3,000 步的模型（2 層，每層 4 個 head）。點任何一個字，藍色越深表示它把越多注意力放在那個字上。

整張注意力矩陣（列：誰在看　行：看誰）

矩陣的右上半永遠是空的。那是 causal mask：每個字只准看自己和前面的字。訓練時整首詩一次餵進去，每個位置都要預測下一個字；如果看得到後面，直接抄答案就好，什麼也學不到。虛線框的字就是被遮住的。

換幾個 head 看看。每個 head 各有自己的 query 和 key，會學到不同的「看法」。這些分工沒有人設計，是訓練自己長出來的。

第五關 · TRANSFORMER

把零件疊起來

整個模型的主幹是一個 [T, C] 的矩陣：T 個 token，每個 token 一個 C 維向量。把它想成一塊共用的白板，每一層讀取上面的內容，再把新的資訊加上去。

  • Attention：在 token 之間搬資訊（上一關）。
  • MLP：對每個 token 各自做非線性運算，消化搬來的資訊。
  • 殘差連接：子層的輸出是「加回」主幹，不是取代。梯度因此有一條全是加法的直達通道。
  • LayerNorm：進每個子層之前先把向量標準化，數值才不會越疊越失控。
試煉疊

依照資料流動的順序，把九個零件排成一個（單層的）GPT。

從下方挑下一個零件。這就是 GPT.forward 和 Block.forward 的內容。

看預測一層一層成形

最後一步是把向量和 embedding 表裡每個字的向量做內積，分數最高的就是模型認為最可能的下一個字。這個動作其實可以提早做：把白板在每一層之後的內容直接拿去比對，就能偷看模型「目前的想法」。

剛查完 embedding 時，模型只知道最後一個字是什麼。每經過一層，前文的資訊被搬進來、被消化，預測就更有把握。

第六關 · TRAINING

開始訓練

零件都齊了。訓練資料不需要人工標註：答案就是同一首詩往後移一格。看到「春」要猜「眠」，看到「春眠」要猜「不」。

猜得有多差，用一個叫 loss 的分數衡量。它只看一件事：模型給「正確答案」多少機率。給 100% 時 loss 是 0；給的機率越低，loss 越大。字表有 1,001 個字，完全亂猜等於每個字給約 0.1%，這時 loss 大約是 6.91。訓練的目標就是把這個數字壓低。

每一步做四件事：正著算出 loss、倒著推出每個旋鈕的梯度（第二關）、擋掉過大的梯度、照梯度更新旋鈕（第三關）。

學過對數的話：這個分數的算法是 −ln(正確答案的機率)，稱為 cross-entropy，亂猜時就是 ln(1001)。

第七關 · GENERATION

一個字一個字寫

訓練好的模型只會做一件事：給它目前的文字，它回傳下一個字的機率分布。寫詩就是反覆做：預測、抽一個字、接上去、再預測。

LLM 的回應一個字一個字出現，是因為它真的就是這樣算出來的。

下一個字的機率（點長條可以自己選）

Temperature 在 softmax 之前把分數除以一個數。調低，差距被放大，模型只選最有把握的字，通順但老套；調到 0 就永遠選第一名。調高，分布變平，用字大膽但容易不通。

Top-k 只留前 k 名。字表有兩千個字，冷門字的機率加起來並不小，砍掉長尾可以避免抽到離譜的字。

注意整個迴圈裡沒有任何一步在檢查內容的真假。模型只負責「接下來什麼看起來合理」。它寫的詩格式工整、用字像唐詩，但全是編的。這就是幻覺（hallucination）的來源，生成式模型本來就是這樣運作。

試煉詩

和模型合寫一首詩：至少親手選三個字，把整首寫完。

點機率長條就是親手選字，藍色的字是你選的。其餘的字按「抽一個字」交給模型。

結語

七關走完了

你走過的路，就是一個 LLM 的全部

  • 文字先變成 token，再變成向量。
  • 向量經過幾層 attention 和 MLP，變成對下一個 token 的預測。
  • 預測和答案的差距是 loss；反向傳播算出每個參數的梯度；Adam 照著梯度更新。
  • 重複幾千次，然後一個字一個字抽樣。

真正的 LLM 用的是同一套演算法，差別在規模：參數從 23 萬變成數千億，資料從一萬五千首詩變成數兆個 token。

接下來

回到終端機，親手跑一次，再打開原始碼對照文件讀。

pnpm train                       # 訓練 3,000 步，約 25 分鐘
