# 06　生成：從機率到文字

對應原始碼：`src/gpt.ts` 的 `samplingDistribution`、`generate`，以及 `src/cli/generate.ts`

訓練好的模型是一個函數：給它一段 token，它回傳下一個 token 的評分。這一章說明怎麼反覆使用這個函數，把它變成一台會寫詩的機器。

## 1. 自回歸迴圈

**自回歸**（autoregressive）的意思是：把自己的輸出當成下一次的輸入。

```
1. 目前的序列：<|end|>
2. 餵進模型，取最後一個位置的 logits        → 對「下一個 token」的評分
3. 把評分變成機率，抽一個 token            → 例如「春」
4. 接到序列後面：<|end|> 春
5. 回到步驟 2，直到抽到 <|end|> 或達到長度上限
```

`generate` 函式就是這個迴圈。LLM 的回應之所以一個字一個字出現，是因為它真的就是一個字一個字算出來的。

幾個細節：

- **只用最後一列。** 模型輸出 `[T, V]`，每個位置都有預測，但前 `T − 1` 個位置預測的是「已經存在的 token」。只有最後一列是對新 token 的預測。
- **Prompt 就是序列的開頭。** 「以『春』開頭寫一首詩」的做法，是讓序列從 `<|end|> 春` 開始。模型分不出哪些是你給的、哪些是它自己寫的，它只是接著往下寫。
- **超過 context 長度就只看最後一段。** `ids.slice(-blockSize)`。位置表只有 `blockSize` 列，更早的內容模型看不到，也就是「被遺忘」了。
- **用 `noGrad` 包起來。** 生成不需要梯度，不必建立計算圖。

## 2. 為什麼要「抽樣」而不是選最高分

最直覺的做法是每次都選機率最高的 token（**greedy decoding**）。問題是它完全沒有隨機性，同樣的開頭永遠寫出同一首詩；而且容易陷入重複，因為「最安全的下一個字」往往把模型帶回它剛剛走過的地方。

模型學到的是一個機率分布。假設「春」後面接「風」的機率是 12%、接「色」9%、接「日」7%，這些都是合理的選擇。依照機率抽樣，才能呈現模型學到的多樣性。

抽樣的實作在 `RNG.multinomial`：把 0 到 1 的區間依照各 token 的機率切成一段一段，丟一個均勻亂數，看它落在哪一段。機率越高的 token 佔的區間越長，越容易被抽中。

## 3. Temperature：調整「大膽程度」

完全照模型的機率抽樣，有時會抽到機率很低、不太通順的字。**Temperature** 讓我們調整分布的尖銳程度：在 softmax 之前，先把 logits 除以溫度 `τ`。

```
p[i] = softmax(logits[i] / τ)
```

以三個 token、logits 為 `[2, 1, 0]` 為例：

| 溫度 | 除完的 logits | 機率 | 效果 |
|------|---------------|------|------|
| `τ = 0.5` | `[4, 2, 0]` | `[0.87, 0.12, 0.02]` | 更集中在最高分 |
| `τ = 1` | `[2, 1, 0]` | `[0.67, 0.24, 0.09]` | 模型原本的分布 |
| `τ = 2` | `[1, 0.5, 0]` | `[0.51, 0.31, 0.19]` | 更平均 |

原理：softmax 看的是 logits 之間的**差距**。除以小於 1 的數會放大差距，指數函數再把放大後的差距變成懸殊的機率；除以大於 1 的數則相反。

- `τ → 0`：等同 greedy，永遠選最高分。程式對 `temperature = 0` 做了特別處理，直接回傳最高分的那一個。
- `τ → ∞`：所有 token 機率相等，完全亂猜。

實務上的取捨是：溫度低，文字通順但保守、容易重複；溫度高，文字有創意但容易出錯。寫詩用 0.7 到 0.9 的效果通常不錯。

## 4. Top-k：砍掉長尾

字表有 2001 個 token。就算每個冷門字的機率只有萬分之一，一千多個冷門字加起來也有可觀的機率。一首 24 字的詩抽 24 次，幾乎一定會抽到一兩個離譜的字。

**Top-k** 只保留分數最高的 `k` 個 token，其餘機率歸零，再重新正規化：

```typescript
cutoff = 第 k 高的 logit
probs[i] = logits[i] >= cutoff ? exp(...) : 0
```

`k = 40` 表示「不管怎樣，只從模型認為最可能的 40 個字裡面選」。Temperature 調整的是分布的形狀，top-k 則是直接截斷，兩者經常搭配使用。

> 另一種常見的做法是 **top-p**（nucleus sampling）：從最高分開始累加機率，加到超過 `p`（例如 0.9）為止，只保留這些 token。它的好處是候選數量會自動調整：模型很有把握時只留兩三個，沒把握時留很多個。這是不錯的練習題，見第 07 章。

## 5. 實際操作

```bash
# 隨機寫五首
pnpm generate

# 以「春」開頭，保守一點
pnpm generate -- --prompt 春 --temperature 0.5

# 更有創意，但更容易不通順
pnpm generate -- --prompt 明月 --temperature 1.2 --top-k 100

# 指定種子，結果可重現
pnpm generate -- --seed 7
```

調整這些參數時，**模型本身完全沒有變**。Temperature 和 top-k 只是改變我們「怎麼從模型給的分布裡挑選」。

## 6. 從這個迴圈看懂 LLM 的幾個特性

### 為什麼會「幻覺」

回頭看這個迴圈：模型唯一的工作是「接下來哪個 token 看起來合理」。迴圈裡沒有任何一步在檢查內容是否為真。對模型來說，寫出一句流暢但錯誤的話，和寫出一句流暢且正確的話，是同一種行為。

我們的詩模型就是很好的例子：它寫出的句子格式工整、用字像唐詩，但那些詩是它「編」出來的，不是它「記得」的。這不是故障，生成式模型本來就是這樣運作的。

### 為什麼不能回頭修改

每個 token 一旦被抽出來，就成為後續所有預測的既定前提。模型即使「發現」前面寫錯了，也只能繼續往下寫。它沒有倒退鍵。

### 為什麼輸出比輸入貴

處理 prompt 只需要一次 forward。生成 `N` 個 token 則需要 `N` 次 forward，每次都得等前一次抽樣完成，無法平行。

### 這個實作浪費在哪裡

仔細看 `generate`：每生成一個 token，就把**整個序列**重新餵進模型。可是因為 causal mask，前面位置的計算結果完全不受後面新增的 token 影響（第 04 章的因果性測試），每次重算都得到一模一樣的數字。

實際的 LLM 會把每一層算過的 key 和 value 存起來，稱為 **KV cache**。新的 token 進來時，只需要計算它自己那一列，再和快取中的 key、value 做 attention。生成每個 token 的成本從 O(T²) 降到 O(T)。本專案為了程式簡單沒有實作，這也是第 07 章的練習題之一。

## 重點回顧

- 生成是一個迴圈：預測、抽樣、接上去、再預測。
- 抽樣保留了模型學到的多樣性；greedy 則容易重複且毫無變化。
- Temperature 在 softmax 之前縮放 logits，控制分布的尖銳程度。
- Top-k 截斷長尾，避免抽到離譜的 token。
- 模型只負責「什麼看起來合理」，流暢不等於正確。
