# 02　Tensor：矩陣版的 autograd

對應原始碼：`src/tensor.ts`、`tests/tensor.test.ts`

上一章的 `Value` 一個節點只裝一個數字。這一章把節點換成矩陣，觀念完全不變：**每個運算做 forward、記住 parents、附上自己的 backward。**

## 1. 設計決定

### 1.1 所有東西都是 2D 矩陣

PyTorch 的 tensor 可以是任意維度，還有一套複雜的 broadcasting 規則。為了讓程式好讀，這個專案規定所有 `Tensor` 都是 `rows × cols` 的 2D 矩陣：

| 資料 | 形狀 |
|------|------|
| 一條序列，每個 token 一個向量 | `[T, C]` |
| 權重矩陣 | `[輸入維度, 輸出維度]` |
| bias、LayerNorm 的 gain | `[1, C]` |
| loss | `[1, 1]` |

代價是沒辦法把整個 batch 疊成一個 3D tensor 一次算完。本專案的做法是「一條序列跑一次 forward，再把 loss 平均」（第 05 章）。少了 batch 維度，attention 的程式碼幾乎和數學式一模一樣。

### 1.2 資料存在一維的 `Float64Array`

矩陣以 **row-major** 順序攤平：第 `i` 列第 `j` 行的元素在 `data[i * cols + j]`。相較於 `number[][]`，連續的記憶體對 CPU 快取友善，V8 也能產生更有效率的機器碼。

選 `Float64Array` 而不是 `Float32Array` 有兩個理由：JavaScript 的數字本來就是 64 位元浮點數，用 32 位元並不會比較快；更重要的是 gradient check 需要高精度，64 位元可以把誤差容忍值設到 `1e-6`，寫錯的 backward 無所遁形。

### 1.3 `grad` 和 `data` 形狀相同

`grad[i]` 就是 `∂loss/∂data[i]`。每個 Tensor 建立時就配置好一塊全為 0 的 `grad`，backward 時各個運算往裡面 `+=`。

### 1.4 `noGrad`

生成文字或計算驗證 loss 的時候不需要梯度。`noGrad(() => ...)` 會暫時關掉一個全域開關，讓運算不記錄 `parents` 和 `backwardFn`。少了這些參照，中間結果用完就能被垃圾回收。

## 2. 矩陣的導數怎麼想

純量的連鎖律是「梯度 × 局部導數」。矩陣運算的輸入和輸出都有很多元素，但原則沒變，只是要把每一條路徑都加起來：

> 輸入的某個元素 `x`，會影響輸出的哪些元素？對每一個受影響的輸出元素，把「該輸出的梯度 × 該輸出對 `x` 的局部導數」加總，就是 `x` 的梯度。

下面每個運算都用這個原則推導。約定：`G` 代表「輸出的梯度」（`out.grad`），這是 backward 時已知的東西；我們要算的是每個輸入的梯度。

## 3. 十三個運算

### 3.1 `matmul`：矩陣乘法

**Forward**：`O = A · B`，形狀 `[n, k] · [k, m] → [n, m]`

```
O[i][j] = Σₚ A[i][p] × B[p][j]
```

**Backward**：`A[i][p]` 出現在第 `i` 列所有輸出 `O[i][0..m]` 的算式裡，每次都乘上 `B[p][j]`。套用原則：

```
dA[i][p] = Σⱼ G[i][j] × B[p][j]        也就是  dA = G · Bᵀ
dB[p][j] = Σᵢ A[i][p] × G[i][j]        也就是  dB = Aᵀ · G
```

這其實是純量乘法規則「梯度乘上對方的值」的矩陣版：`A` 的梯度用到 `B`，`B` 的梯度用到 `A`。

記憶法：看形狀。`dA` 必須和 `A` 一樣是 `[n, k]`，手上有 `G [n, m]` 和 `B [k, m]`，唯一合理的組合就是 `G · Bᵀ`。

**迴圈順序**：程式裡的三層迴圈是 `i → p → j`，而不是教科書的 `i → j → p`。這樣最內層是 `O[i][j] += A[i][p] × B[p][j]`，`j` 遞增時 `O` 和 `B` 都沿著同一列連續讀寫。記憶體連續存取比跳著存取快上好幾倍。訓練時絕大部分的時間都花在這個函式上，所以這是全專案唯一刻意做的效能最佳化。

### 3.2 `transpose`：轉置

`O[j][i] = A[i][j]`。每個元素只是換位置，backward 就把梯度換回原位：`dA[i][j] += G[j][i]`。

### 3.3 `add`：相加（含 broadcast）

同形狀時，`O = A + B`，梯度原封不動分給兩邊：`dA += G`、`dB += G`。

當 `B` 是 `[1, C]` 的列向量（bias）時，它會被加到 `A` 的**每一列**。`B[j]` 影響了第 `j` 行的所有輸出，所以它的梯度是整行加總：

```
dB[j] = Σᵢ G[i][j]
```

這是 broadcasting 的通則：**forward 時被複製了幾次，backward 時就要把那幾份梯度加起來。**

### 3.4 `scale`：乘上常數

`O = s × A`，`dA += s × G`。

### 3.5 `sliceCols` 與 `concatCols`

兩者互為反運算，都只是搬資料：

- `sliceCols` 取出某幾行。Backward 把梯度放回原本的位置，沒被取到的行梯度是 0。
- `concatCols` 把幾個矩陣左右接起來。Backward 把梯度切開，各自送回去。

它們用於 multi-head attention：把 `C` 維切成幾個 head 各自計算，再接回來。

### 3.6 `embedding`：查表

**Forward**：`O` 的第 `t` 列等於 `table` 的第 `ids[t]` 列。

**Backward**：只有被查到的那幾列有梯度。同一列被查了兩次（例如一首詩裡「山」出現兩次），就會收到兩份梯度，所以用 `+=`。

每一步訓練只有出現在該 batch 裡的字，embedding 才會被更新，其餘的字梯度為 0。

> 查表其實等價於「one-hot 向量乘上矩陣」。直接查表只是省略掉一大堆乘以 0 的計算。

### 3.7 `gelu`：啟動函數

```
gelu(x) = 0.5 × x × (1 + tanh(√(2/π) × (x + 0.044715 × x³)))
```

形狀是平滑版的 ReLU：負數大多被壓到接近 0，正數幾乎原樣通過。它逐元素運算，所以 backward 也是逐元素乘上導數（用乘法規則和連鎖律展開即可，見程式碼）。

為什麼模型需要非線性函數，第 04 章會說明。

### 3.8 `softmax`：把分數變成機率

**Forward**：對每一列

```
p[j] = e^(x[j]) / Σₖ e^(x[k])
```

指數函數保證每一項都是正的，除以總和保證加起來等於 1。分數高的 token 拿到大部分的機率，而且差距會被指數放大。

**數值穩定**：`e^1000` 會溢位成 `Infinity`。因為分子分母同乘一個常數不影響結果，所以先把整列減掉最大值，最大的那項變成 `e^0 = 1`，其餘都小於 1，永遠不會溢位。

**Backward**：`x[i]` 影響的不只是 `p[i]`，還會透過分母影響同一列的每一個 `p[j]`。局部導數是

```
∂p[j]/∂x[i] = p[j] × (δᵢⱼ − p[i])        δᵢⱼ 在 i = j 時為 1，否則為 0
```

加總所有路徑：

```
dx[i] = Σⱼ G[j] × p[j] × (δᵢⱼ − p[i])
      = p[i] × (G[i] − Σⱼ G[j] × p[j])
```

括號裡的 `Σⱼ G[j] × p[j]` 對整列是同一個數，程式先把它算好（變數 `dot`），再套到每個元素上。

### 3.9 `maskFuture`：遮住未來

**Forward**：把行 `j` 大於列 `i` 的位置設成 `−∞`，其餘不變。

**Backward**：被遮住的位置輸出固定是 `−∞`，和輸入無關，梯度為 0；其餘位置梯度原樣通過。

它一定搭配 `softmax` 使用：`e^(−∞) = 0`，被遮住的位置機率剛好是 0。為什麼需要遮，見第 04 章的 causal mask。

### 3.10 `layerNorm`：層正規化

**Forward**：對每一列（一個 token 的向量）

```
μ  = 該列的平均
σ  = √(該列的變異數 + ε)
x̂ = (x − μ) / σ                 → 平均 0、變異數 1
y  = x̂ × gain + bias            → gain、bias 是可學習的 [1, C] 向量
```

**Backward**：`gain` 和 `bias` 很單純，套用乘法和加法規則，再把各列加總（因為 broadcast）：

```
dgain[j] = Σ列 G[j] × x̂[j]
dbias[j] = Σ列 G[j]
```

對 `x` 的梯度比較繞，因為 `x[i]` 經由三條路徑影響輸出：直接影響 `x̂[i]`、經由 `μ` 影響整列、經由 `σ` 影響整列。令 `g[j] = G[j] × gain[j]`（對 `x̂` 的梯度），`n` 為該列的元素數。

先求局部導數。`σ` 對 `x[i]` 的導數是 `(x[i] − μ) / (nσ) = x̂[i] / n`，所以

```
∂x̂[j]/∂x[i] = (δᵢⱼ − 1/n) / σ  −  x̂[j] × x̂[i] / (nσ)
               └── 經由 x 與 μ ──┘   └──── 經由 σ ────┘
```

加總所有 `j`：

```
dx[i] = ( g[i] − mean(g) − x̂[i] × mean(g × x̂) ) / σ
```

三項各有意義：

- `g[i]`：直接路徑。
- `− mean(g)`：減掉平均。因為 forward 減過 `μ`，「整列一起加上同一個數」對輸出毫無影響，所以梯度裡「整列一起動」的成分必須是 0。
- `− x̂[i] × mean(g × x̂)`：因為 forward 除過 `σ`，「整列等比例放大」對輸出也毫無影響，梯度裡這個方向的成分同樣要拿掉。

這個式子很容易推錯，所以測試中 `layerNorm` 對輸入、`gain`、`bias` 三者都做了 gradient check。

### 3.11 `crossEntropy`：損失函數

**Forward**：`logits [T, V]` 的每一列先做 softmax 得到機率 `p`，取出正確答案的機率，取 `−log`，最後對 `T` 個位置平均：

```
loss = (1/T) × Σₜ −log p[t][targets[t]]
```

**Backward**：單看一列。把 softmax 代進去展開：

```
−log p[y] = −x[y] + log Σₖ e^(x[k])
```

對 `x[i]` 微分，第一項在 `i = y` 時是 `−1`；第二項是 `e^(x[i]) / Σₖ e^(x[k])`，剛好就是 `p[i]`。於是

```
∂loss/∂x[i] = p[i] − (i 是正確答案 ? 1 : 0)
```

也就是**「預測的機率分布」減掉「正確答案的 one-hot」**。這是整個專案最漂亮的一條式子：

- 正確答案那一格：`p − 1` 是負的 → 梯度下降會把這個分數**推高**。
- 其他每一格：`p` 是正的 → 分數被**壓低**，而且原本給的機率越高、壓得越用力。
- 當模型給正確答案的機率接近 1，梯度趨近 0，自然就不再修正。

把 softmax 和 log 合成一個運算，除了式子簡單，數值上也比較穩定。分開算的話，機率可能下溢成 0，`log(0)` 會得到 `−∞`。

### 3.12 `meanScalars`：平均

把一個 batch 中每條序列的 loss 平均起來。Backward 把梯度除以個數，平分給每一個 loss。

## 4. Gradient check：最重要的測試

十三個 backward 都是手寫的，只要其中一個寫錯，模型就會悄悄變差。Gradient check 用第 01 章的「笨方法」來對答案：

```typescript
// tests/helpers.ts
fn().backward()                                  // autograd 的答案
for (每個輸入的每個元素) {
  x += h;  const plus  = fn().item()
  x -= 2h; const minus = fn().item()
  const numeric = (plus − minus) / 2h            // 數值微分的答案
  expect(numeric).toBeCloseTo(autograd 的梯度)
}
```

幾個細節：

- **中央差分**：用 `(f(x+h) − f(x−h)) / 2h` 而不是 `(f(x+h) − f(x)) / h`。前者的誤差和 `h²` 成正比，後者和 `h` 成正比，精確得多。
- **把矩陣壓成純量**：backward 需要純量的起點。`toScalar` 用固定的隨機權重把輸出加權加總，這樣每個輸出元素都有不同的梯度，位置寫錯也抓得到。如果只是單純加總，每個輸出的梯度都是 1，很多錯誤會被掩蓋。
- **整個模型也做一次**：`tests/gpt.test.ts` 對完整 GPT 的每一個參數張量抽查數個元素。單獨正確的運算，組合起來也必須正確。

這 55 個測試通過，代表的是「這套 autograd 算出來的梯度，和微積分的定義一致」。之後訓練不順利時，就可以排除梯度算錯的可能，專心檢查其他地方。

## 重點回顧

- Tensor 和 Value 是同一個想法，只是節點從數字變成矩陣。
- 推導 backward 的通用方法：找出某個輸入影響了哪些輸出，把所有路徑的「梯度 × 局部導數」加起來。
- Broadcast 的 backward 是加總。
- `crossEntropy` 的梯度是 `p − onehot`。
- 手寫的 backward 一定要用數值微分驗證。
