# 04　GPT：模型的架構

對應原始碼：`src/nn.ts`、`src/gpt.ts`

這一章說明「輸入 token ids、輸出下一個 token 的評分」的函數長什麼樣子。這個架構稱為 **decoder-only Transformer**，GPT、Claude、Llama 的骨幹都是它。

## 1. 形狀之旅

先看整體。一條長度 `T` 的序列經過模型時，形狀的變化是：

```
token ids                           長度 T 的整數陣列
  │ token embedding + position embedding
  ▼
x                                   [T, C]     每個 token 一個 C 維向量
  │ Block × nLayer
  ▼
x                                   [T, C]     形狀不變，內容不斷被修改
  │ LayerNorm → 乘上 wteᵀ
  ▼
logits                              [T, V]     每個位置對 V 個 token 的評分
```

中間那個 `[T, C]` 的矩陣是整個模型的主幹，常被稱為**殘差流**（residual stream）。可以把它想成一塊共用的白板：每個 token 有自己的一列，每一層都在讀取白板上的內容，再把新的資訊**加**上去。

`logits` 的第 `t` 列，是模型看完第 0 到第 `t` 個 token 之後，對「第 `t+1` 個 token 是誰」的評分。所以一次 forward 會同時產生 `T` 個預測。

## 2. Embedding：把 id 變成向量

### 2.1 Token embedding（`wte`）

Token id 只是編號，數字大小沒有意義（id 812 的「春」並沒有比 id 37 的「不」大）。所以第一步是查表，把每個 id 換成一個 `C` 維的向量：

```
wte：[V, C] 的矩陣，第 i 列是 token i 的向量
```

這些向量一開始是亂數，是**可以學習的參數**。訓練過程中，用法相近的字（例如「山」和「峰」）因為常出現在類似的上下文，收到類似的梯度，向量會漸漸靠近。模型對「字的意義」的理解，就存在這張表裡。

### 2.2 Position embedding（`wpe`）

Attention（下一節）有一個特性：它把輸入當成一個**集合**，本身並不知道誰先誰後。但語言的順序顯然很重要，「我打你」和「你打我」意思完全相反。

解法很直接：再準備一張表，每個**位置**一個向量，加到 token 的向量上。

```
wpe：[blockSize, C] 的矩陣，第 p 列是「位置 p」的向量
x[t] = wte[ids[t]] + wpe[t]
```

於是第 3 個位置的「山」和第 8 個位置的「山」有不同的向量。位置向量同樣是學出來的。在五言詩裡，模型會學到「位置 6 和 18 是逗號、位置 12 和 24 是句號」這類規律。

`blockSize` 就是 **context 長度的上限**：位置表只有這麼多列，超過就沒有向量可用。這是「context window」這個限制最直接的來源。

> 這種做法稱為 learned absolute position embedding，是 GPT-2 的做法。現代模型多改用 RoPE 等相對位置編碼，讓模型更容易推廣到較長的序列，但目的相同。

## 3. Self-attention：讓 token 互相交換資訊

查完 embedding 之後，每個 token 的向量只包含自己的資訊。要預測下一個字，必須知道前面寫了什麼。Attention 就是讓資訊在 token 之間流動的機制，也是 Transformer 唯一讓不同位置互相溝通的地方。

### 3.1 直覺：query、key、value

想像每個 token 都在做兩件事：**發問**和**提供資訊**。

每個 token 用三個線性層，從自己的向量產生三個向量：

| 向量 | 意義 | 比喻 |
|------|------|------|
| **query** | 我在找什麼 | 搜尋關鍵字 |
| **key** | 我有什麼 | 文件的標籤 |
| **value** | 如果你選了我，我給你什麼 | 文件的內容 |

第 `i` 個 token 拿自己的 query，去和每個 token 的 key 做**內積**。內積衡量兩個向量有多「對得上」：方向越一致，數值越大。這個數值就是「`i` 對 `j` 有多感興趣」的分數。

分數經過 softmax 變成一組加總為 1 的權重，再用這組權重把所有 token 的 **value** 加權平均。結果就是第 `i` 個 token 從其他 token 那裡收集到的資訊。

舉例：模型正要預測對句的第 3 個字時，它的 query 可能在問「上一句的第 3 個字是什麼詞性？」，而上一句第 3 個字的 key 剛好寫著「我是第 3 個字」，兩者內積很大，於是那個字的 value（帶著詞性資訊）就被搬過來了。這些「問題」和「標籤」沒有人設計，全都是訓練中自己學出來的。

### 3.2 算式

以一個 head 為例，`Q`、`K`、`V` 都是 `[T, d]`（`d` 是 head 的維度）：

```
scores    = Q · Kᵀ / √d              [T, T]   scores[i][j] = qᵢ · kⱼ / √d
attention = softmax(mask(scores))    [T, T]   每一列加總為 1
output    = attention · V            [T, d]   output[i] = Σⱼ attention[i][j] × vⱼ
```

對照 `src/gpt.ts` 的 `CausalSelfAttention.forward`，程式碼和這三行幾乎一字不差。

### 3.3 為什麼要除以 √d

內積是 `d` 個乘積的總和。如果 query 和 key 的每個分量大約是變異數 1 的亂數，內積的變異數就是 `d`，標準差是 `√d`。維度越高，分數的絕對值越大。

Softmax 對數值大小很敏感：輸入的差距一大，輸出就會變成「一個接近 1、其餘接近 0」。這時 attention 只看一個 token，而且 softmax 在這種飽和狀態下梯度幾乎是 0，模型學不動。除以 `√d` 把分數的標準差拉回 1 左右，不論維度多大，softmax 都從一個溫和的分布開始。

### 3.4 Causal mask：不准偷看答案

訓練時，我們把整首詩一次餵進去，同時要求模型在每個位置預測下一個字。問題來了：位置 3 要預測位置 4 的字，可是位置 4 的字就擺在輸入裡。如果 attention 可以看到它，模型只要學會「把後面那個字抄過來」就能拿滿分，什麼也沒學到。

**Causal mask** 規定：第 `i` 個 token 只能看第 0 到第 `i` 個 token。做法是在 softmax 之前，把 `scores` 中 `j > i` 的位置設成 `−∞`：

```
scores（mask 之後）              attention（softmax 之後）
[ 0.3  −∞   −∞   −∞ ]            [ 1.00  0     0     0    ]
[ 0.1  0.5  −∞   −∞ ]     →      [ 0.40  0.60  0     0    ]
[ 0.2  0.1  0.9  −∞ ]            [ 0.25  0.23  0.51  0    ]
[ 0.4  0.3  0.2  0.6]            [ 0.25  0.23  0.21  0.31 ]
```

`e^(−∞) = 0`，被遮住的位置權重剛好是 0，剩下的位置自動重新分配成加總為 1。注意第一列：第一個 token 只能看自己，權重必然是 1。

這個設計帶來兩個重要的結果：

1. **訓練很有效率。** 一條長度 `T` 的序列，一次 forward 就提供 `T` 題獨立的練習，而且彼此不會作弊。
2. **訓練和生成的條件一致。** 生成時未來的字本來就還不存在。因為有 mask，訓練時每個位置看到的東西，和生成時完全相同。

測試中的「因果性」測試直接驗證這件事：把序列後半段換掉，前半段每個位置的輸出一個位元都不會變。

### 3.5 Multi-head：同時問好幾個問題

一組 query/key 只能表達一種「關注的方式」。但預測下一個字時，往往需要同時留意好幾件事：前一個字是什麼、上一句同位置的字是什麼、這首詩目前寫到第幾個字。

**Multi-head attention** 把 `C` 維切成 `nHead` 份，每一份各自獨立做一次完整的 attention，最後把結果接起來。本專案預設 `C = 64`、`nHead = 4`，每個 head 是 16 維。

實作上先用三個 `[C, C]` 的線性層一次算出完整的 `Q`、`K`、`V`，再用 `sliceCols` 切成各個 head。參數數量和單一 head 相同，只是把同樣的容量拆成幾個可以各自專精的小組。

各個 head 的輸出用 `concatCols` 接回 `[T, C]` 之後，再通過一個線性層 `proj`。它負責把各 head 收集到的資訊混合起來，寫回殘差流。

### 3.6 成本

`scores` 是一個 `[T, T]` 的矩陣，每一對 token 都要算一次。序列長度加倍，計算量和記憶體變成四倍。這個 **O(T²)** 是 context window 無法無限加大的主因。

## 4. MLP：消化資訊

Attention 做的事是「搬運」：把其他位置的資訊加權平均過來。它本身幾乎是線性的，沒有太多「運算」能力。

**MLP**（也叫 feed-forward network）負責「消化」。它對每個 token **獨立**運作，不看其他位置：

```
MLP(x) = proj( gelu( fc(x) ) )

fc：   [C, 4C]   放大到 4 倍寬
gelu：           非線性
proj： [4C, C]   縮回原本的寬度
```

### 4.1 為什麼需要非線性

兩個線性層直接相接，數學上等於一個線性層：`(x·W₁)·W₂ = x·(W₁·W₂)`。不管疊幾層，整個網路都只能表示線性函數，連 XOR 這麼簡單的東西都學不會。

在中間放一個非線性函數（`gelu`），網路才有能力表示複雜的函數。直覺上，`gelu` 讓每個隱藏神經元變成一個「偵測器」：輸入符合某種特徵時輸出正值，否則輸出接近 0。

### 4.2 為什麼要先放大再縮小

中間層越寬，偵測器越多，能辨認的特徵組合也越多。4 倍是原始 Transformer 論文沿用至今的經驗值。在本專案的每個 Block 中，MLP 佔了大約三分之二的參數。

一種常見的看法是：attention 負責「從哪裡拿資訊」，MLP 則像一個巨大的查詢表，存著「看到這種特徵組合時，應該輸出什麼」。模型記住的知識大多存放在 MLP 的權重裡。

## 5. 殘差連接與 LayerNorm：讓深層網路訓練得動

Attention 和 MLP 是模型的「內容」。接下來兩個設計本身不做什麼運算，但少了它們，模型疊深之後就無法訓練。

### 5.1 殘差連接

每個子層都不是直接取代 `x`，而是把結果**加**回去：

```typescript
x = add(x, attn(ln1(x)))
x = add(x, mlp(ln2(x)))
```

兩個角度理解它的作用：

**Forward 的角度**：每個子層只需要學「要在現有的向量上**修改**什麼」，不必重新產生整個向量。如果某一層沒什麼好做的，輸出 0 就等於直接跳過。

**Backward 的角度**：第 01 章提過，加法把梯度原封不動地傳給兩邊。於是從 loss 到最底層的 embedding，存在一條全部由加法構成的通道，梯度可以暢通無阻地流回去。沒有殘差連接的話，梯度每經過一層就要乘上該層的局部導數，連乘幾十次之後不是趨近 0 就是暴增，前面的層根本收不到有用的訊號。

### 5.2 LayerNorm

每一層都在往殘差流裡加東西，向量的大小會逐漸漂移。LayerNorm 在每個子層的**入口**把向量重新標準化（平均 0、變異數 1），讓每一層看到的輸入永遠在差不多的數值範圍內，訓練因此穩定得多。

`gain` 和 `bias` 這兩個可學習的參數（初始為 1 和 0）讓模型保有彈性：如果標準化之後的尺度不是最適合的，可以自己調回來。

### 5.3 Pre-norm

注意 LayerNorm 的位置：它放在子層**裡面**（`attn(ln1(x))`），而不是加完之後才做。這稱為 **pre-norm**。殘差的主幹上因此完全沒有任何運算擋路，梯度的高速公路保持純粹的加法。

原始的 Transformer 論文把 norm 放在加法之後（post-norm），GPT-2 之後幾乎都改成 pre-norm，因為深層模型訓練起來穩定得多。

主幹上沒有 norm 的代價是，最後出來的向量大小不受控制。所以在輸出之前還要再做一次 LayerNorm（`lnF`）。

## 6. 輸出層與 weight tying

經過所有 Block 之後，每個位置的向量已經整合了前文的資訊。最後一步是把 `C` 維向量變成對 `V` 個 token 的評分：

```typescript
return matmul(x, transpose(this.wte.weight))    // [T, C] · [C, V] → [T, V]
```

這裡沒有另外準備一個輸出矩陣，而是直接**重用 token embedding 表**。展開來看：

```
logits[t][v] = x[t] · wte[v]
```

第 `v` 個 token 的分數，就是「最後的向量」和「token `v` 的 embedding」的內積，也就是兩者有多像。模型的工作因此可以這樣理解：**把輸入的向量一路加工，直到它變得像「下一個 token」的 embedding。**

這個做法稱為 **weight tying**，有兩個好處：

- 少一個 `[C, V]` 的矩陣。對本專案來說是 128,064 個參數，超過總數的一半。
- 輸入端和輸出端共用同一份對 token 的理解。一個字在輸入端學到的東西，輸出端立刻用得上；反之亦然。

在 autograd 裡，`wte` 這個 Tensor 會從兩條路徑收到梯度（embedding 查表、輸出層的矩陣乘法），因為 backward 一律使用 `+=`，兩份梯度自動相加，不需要任何特別處理。

## 7. 初始化

參數的初始值看似細節，卻決定了訓練能不能順利起步。

- **權重**用標準差 0.02 的常態分布。夠小，讓初始的 logits 都接近 0，模型一開始對每個 token 給出幾乎相同的機率。
- **Bias** 初始為 0，**LayerNorm 的 gain** 初始為 1。
- **每個子層最後寫回殘差流的 `proj`** 用更小的標準差 `0.02 / √(2 × nLayer)`。殘差流是所有子層輸出的總和，共有 `2 × nLayer` 個子層在往裡面加東西。把每一份縮小，總和的變異數才不會隨層數增加。

### 用初始 loss 檢查

如果初始化正確，模型一開始應該是「完全沒概念」，對 `V` 個 token 給出均勻的機率 `1/V`。這時的 loss 是

```
−log(1/V) = ln(V) = ln(2001) ≈ 7.60
```

實際訓練的第 0 步印出 `train 7.590`，符合預期。如果這個數字明顯偏高，代表模型一開始就「自信地猜錯」，通常是初始化的尺度太大。這是訓練任何語言模型時第一個該看的數字。

## 8. 參數都在哪裡

預設設定（`V = 2001`、`blockSize = 25`、`C = 64`、`nLayer = 2`、`nHead = 4`）下：

| 元件 | 形狀 | 參數數 |
|------|------|--------|
| `wte`（同時是輸出層） | `[2001, 64]` | 128,064 |
| `wpe` | `[25, 64]` | 1,600 |
| 每個 Block：`ln1`、`ln2` | `[1, 64]` × 4 | 256 |
| 每個 Block：`query`、`key`、`value` | `[64, 64]` × 3 | 12,288 |
| 每個 Block：attention 的 `proj` | `[64, 64]` + `[1, 64]` | 4,160 |
| 每個 Block：MLP 的 `fc` | `[64, 256]` + `[1, 256]` | 16,640 |
| 每個 Block：MLP 的 `proj` | `[256, 64]` + `[1, 64]` | 16,448 |
| Block 小計 | × 2 層 | 99,584 |
| `lnF` | `[1, 64]` × 2 | 128 |
| **合計** | | **229,376** |

小模型的參數大多花在 embedding 表上。模型放大時，`C` 和 `nLayer` 增加，Block 的參數以 `C²` 的速度成長，很快就會遠遠超過 embedding。

## 重點回顧

- 模型的主幹是一個 `[T, C]` 的殘差流，每一層讀取它、再把修改加回去。
- Embedding 把 token id 和位置各自變成向量後相加。
- Attention 是唯一讓 token 之間交換資訊的地方：query 和 key 的內積決定權重，再對 value 加權平均。
- Causal mask 讓每個位置只能看到過去，使一條序列能同時提供 `T` 題練習。
- MLP 對每個 token 獨立做非線性運算。
- 殘差連接提供梯度的直達通道；LayerNorm 穩定每一層的輸入。
- 輸出層重用 embedding 表：分數是「最後的向量」和「各個 token 的 embedding」的內積。
