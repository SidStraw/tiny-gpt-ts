# 05　訓練：讓模型從資料中學習

對應原始碼：`src/data.ts`、`src/optim.ts`、`src/trainer.ts`、`src/cli/train.ts`

前面幾章準備好了三樣東西：會算梯度的引擎、把文字變成數字的 tokenizer、一個充滿亂數的模型。這一章把它們接起來。

## 1. 訓練目標：預測下一個 token

### 1.1 不需要標註的資料

語言模型的訓練資料就是文字本身，「正確答案」是把同一段文字往後移一格：

```
輸入 x： <|end|>  春   眠   不   覺   曉
答案 y：   春    眠   不   覺   曉   ，
```

第 `t` 個位置的任務是：看到 `x[0..t]`，預測 `y[t]`。因為答案來自資料本身，不需要人工標註，這種做法稱為**自監督學習**（self-supervised learning）。這也是 LLM 能夠用整個網際網路的文字來訓練的原因。

`Dataset.sample` 做的就是這件事：隨機抽一份文件，前後加上結束符號，切出 `x` 和往後移一格的 `y`。

### 1.2 一條序列等於 T 題練習

因為有 causal mask（第 04 章），位置 `t` 的輸出只依賴 `x[0..t]`。一次 forward 同時產生所有位置的預測，每個位置都是一題獨立、無法作弊的練習：

```
看到 <|end|>               → 預測「春」
看到 <|end|> 春            → 預測「眠」
看到 <|end|> 春 眠         → 預測「不」
……
```

一首 24 字的詩加上結束符號，一次 forward 就練習了 25 題。

## 2. Loss：衡量預測得有多差

### 2.1 Cross-entropy

對每一題，模型給出一個涵蓋 `V` 個 token 的機率分布。我們只關心一個數字：**模型給正確答案多少機率？**

```
loss = −log( 正確答案的機率 )
```

| 給正確答案的機率 | loss |
|------------------|------|
| 1.0（完全確定且正確） | 0 |
| 0.5 | 0.69 |
| 0.1 | 2.30 |
| 1/2001（均勻亂猜） | 7.60 |
| 0.0001（自信地猜錯） | 9.21 |

`−log` 有兩個好性質：答對且有信心時趨近 0；越是自信地猜錯，懲罰越重，而且沒有上限。

整個 batch 的 loss 是所有題目的平均。它的梯度就是第 02 章推導的 `p − onehot`。

### 2.2 怎麼解讀 loss 的數值

Loss 的單位不直觀，取指數會好懂得多。`e^loss` 稱為 **perplexity**（困惑度），意思是「模型平均在幾個選項之間猶豫」：

- loss 7.60 → perplexity 2001：在整個字表裡亂猜。
- loss 4.6 → perplexity 約 100：平均來說，相當於在 100 個字裡面選。

對詩來說，perplexity 不可能降到 1。「春」後面可以接的字本來就有很多，資料本身就帶有不確定性。模型能做到的最好情況，是學會這個真實的分布。

### 2.3 為什麼是這個 loss

最小化 cross-entropy，等價於**最大化模型賦予訓練資料的機率**（maximum likelihood）。一整首詩的機率是每個字的條件機率相乘；取 log 之後連乘變成連加，再加上負號，就是我們的 loss。所以訓練的目標可以說成：調整參數，讓模型覺得「真實的詩」盡可能合理。

## 3. Mini-batch

### 3.1 為什麼一次用一小批

- 用**全部**資料算一次梯度再更新：方向最準，但一萬多首詩才走一步，太慢。
- 用**一首**詩算梯度就更新：很快，但單一樣本的梯度雜訊太大，方向亂跳。

折衷方案是每步隨機抽 `B` 首（預設 32），把它們的 loss 平均。這稱為**隨機梯度下降**（stochastic gradient descent）。平均之後雜訊降低，而且每一步的成本固定，和資料集大小無關。

梯度裡的雜訊也不全是壞事，它讓模型不容易卡在一個只對特定樣本有效的解。

### 3.2 本專案的做法

```typescript
// src/trainer.ts
export function batchLoss(model, batch) {
  return meanScalars(batch.map((example) => model.loss(example.x, example.y)))
}
```

每條序列各自跑一次 forward，建立各自的計算圖；`meanScalars` 把 32 個 loss 接成一張大圖。呼叫一次 `backward()`，梯度就流過全部 32 條序列，在共用的參數上累加。

這和真實框架的做法不同。PyTorch 會把整個 batch 疊成 `[B, T, C]` 的 3D tensor 一次算完，才能發揮 GPU 的平行能力。代價是同一個 batch 內的序列必須等長，短的要補上 padding，還要處理 padding 的 mask。我們一條一條算，長度不同也無所謂，程式因此簡單得多。兩種做法算出來的梯度是相同的。

## 4. 一步訓練

`trainStep` 是整個訓練的核心，只有四個動作：

```typescript
optimizer.zeroGrad()                                  // 0. 上一步的梯度歸零
const loss = batchLoss(model, batch)                  // 1. forward：算 loss，同時建計算圖
loss.backward()                                       // 2. backward：算出每個參數的梯度
const gradNorm = clipGradNorm(model.parameters(), 1)  // 3. 梯度太大就縮小
optimizer.step(lr)                                    // 4. 依梯度更新參數
```

接下來逐一說明第 3、4 步的設計。

## 5. AdamW：聰明一點的梯度下降

### 5.1 單純的梯度下降有什麼問題

`w ← w − lr × g` 有兩個實際的困難：

1. **雜訊。** Mini-batch 的梯度每一步都在抖動，直接照著走會左搖右晃。
2. **尺度不一。** 不同參數的梯度大小可能差好幾個數量級。常見字的 embedding 每一步都被更新，罕見字偶爾才輪到一次。同一個學習率不可能同時適合所有參數：對某些太大（發散），對另一些又太小（學不動）。

### 5.2 Adam 的兩個移動平均

Adam 為**每一個**參數維護兩個數字：

```
m ← β₁ × m + (1 − β₁) × g        梯度的移動平均        （β₁ = 0.9）
v ← β₂ × v + (1 − β₂) × g²       梯度平方的移動平均    （β₂ = 0.99）
```

**`m` 是動量**（momentum）。它是最近幾步梯度的加權平均。連續幾步方向一致的成分會累積起來，忽正忽負的雜訊則互相抵消。像一顆有慣性的球，不會因為一個小顛簸就改變方向。

**`v` 估計梯度的典型大小。** 梯度一向很大的參數，`v` 就大；梯度一向很小的參數，`v` 就小。

更新量是兩者的比值：

```
w ← w − lr × m / (√v + ε)
```

除以 `√v` 的效果是**為每個參數自動調整步伐**。梯度長期很大的參數，被除以一個大的數，走小步；梯度長期很小的參數走大步。`m / √v` 的大小大致落在 ±1 之間，所以不管梯度原本的尺度是多少，每個參數每一步大約移動 `lr` 這麼多。學習率因此有了明確的意義，也好調整得多。

`ε`（`1e-8`）只是避免除以 0。

### 5.3 Bias correction

`m` 和 `v` 從 0 開始。第一步之後 `m = 0.1 × g`，只有真實梯度的十分之一。這不是因為梯度小，純粹是因為平均還沒「暖機」。

修正方式是除以 `(1 − βᵗ)`，`t` 是目前的步數：

```
m̂ = m / (1 − β₁ᵗ)        第 1 步：除以 0.1，剛好還原成 g
v̂ = v / (1 − β₂ᵗ)        步數一多，分母趨近 1，修正自動消失
```

### 5.4 Weight decay 與「W」

**Weight decay** 在每一步把權重往 0 拉一點點：

```
w ← w − lr × weightDecay × w
```

它是一種**正則化**（regularization）：限制權重不能無止境地變大，迫使模型用較「樸素」的方式解釋資料，比較不容易死背訓練集。

AdamW 的「W」指的是 decay 的**施加方式**。早期的做法是把 `weightDecay × w` 加進梯度 `g` 裡，但這樣它會跟著被 `√v` 除，梯度大的參數實際受到的 decay 反而變小，效果很不一致。AdamW 把 decay 獨立出來，直接作用在權重上（decoupled weight decay）。程式裡這兩項是分開加的：

```typescript
p.data[j] -= lr * (mHat / (Math.sqrt(vHat) + eps) + decay * p.data[j])
```

**哪些參數要 decay？** 只有矩陣型的權重（線性層的 weight、embedding 表）。Bias 和 LayerNorm 的 `gain` 不做，因為它們的作用是平移和縮放，把它們往 0 拉沒有正則化的意義，反而有害。程式用 `p.rows > 1` 來區分，剛好利用了本專案「bias 和 gain 都是 `[1, n]`」這個約定。

## 6. 學習率排程

學習率不是固定的。`learningRate` 函式讓它隨訓練進度變化：

```
lr
 │    ╭──╮
 │   ╱    ╲___
 │  ╱         ╲____
 │ ╱               ╲______
 │╱                       ╲________
 └──────────────────────────────────► step
   暖身          cosine 衰減
```

### 6.1 Warmup

最初的 100 步，學習率從接近 0 線性上升到最大值。理由有兩個：

- 參數剛初始化時是亂數，梯度的方向很不可靠，大步前進容易走到很糟的區域。
- Adam 的 `v` 需要幾十步才能累積出可靠的估計。在那之前，步伐大小的自動調整並不準確。

### 6.2 Cosine 衰減

暖身之後，學習率沿著半個 cosine 曲線，平滑地降到最大值的 10%。

訓練初期離好的解很遠，大步走才有效率。越接近終點，越需要小步微調。步伐太大會在最佳點附近來回彈跳，永遠落不進去。Cosine 只是一條方便的平滑曲線：前段降得慢（保持高學習率久一點）、中段降得快、尾段又趨緩。

## 7. Gradient clipping

偶爾會遇到一個梯度特別大的 batch。照著走的話，一步就可能把已經學好的參數踢壞，loss 瞬間暴增。

`clipGradNorm` 計算所有參數的梯度合起來的長度（L2 norm）。超過門檻（預設 1）時，把**所有**梯度乘上同一個係數，讓長度剛好等於門檻：

```typescript
if (norm > maxNorm) 所有梯度 *= maxNorm / norm
```

重點是**等比例縮小**：只改變步伐的大小，不改變方向。正常的 batch 不受影響，它只在意外發生時踩煞車。

## 8. 訓練集、驗證集與 overfitting

### 8.1 為什麼要留一部分資料不訓練

模型有 23 萬個參數，足以把不少訓練資料直接背下來。背得越熟，訓練 loss 越低，但這不代表它學會了「怎麼寫詩」。

所以 `splitDocs` 把 10% 的詩留作**驗證集**，永遠不拿來訓練。訓練過程中定期在驗證集上算 loss：

- **訓練 loss**：模型對「看過的詩」預測得多準。
- **驗證 loss**：模型對「沒看過的詩」預測得多準。這才是真正的能力。

### 8.2 讀懂 loss 曲線

| 現象 | 意義 | 對策 |
|------|------|------|
| 兩者一起下降 | 模型正在學習通用的規律 | 繼續訓練 |
| 訓練 loss 繼續降，驗證 loss 停住甚至回升 | **Overfitting**：開始死背訓練集 | 提早停止、增加資料、加強正則化、縮小模型 |
| 兩者都很高，降不下來 | **Underfitting**：模型容量不足，或訓練有問題 | 放大模型、檢查學習率 |
| Loss 突然暴增或變成 `NaN` | 訓練發散 | 降低學習率、檢查 gradient clipping |

### 8.3 本專案的實際結果

以預設設定在 13,527 首詩上訓練 3,000 步：

| 步數 | 訓練 loss | 驗證 loss | 當時寫出的詩 |
|------|-----------|-----------|--------------|
| 0 | 7.59 | 7.58 | 騷延求剪僧翔信信陸夷康迥酒傳流暎泊立簪雁庾冷銀崇禍 |
| 100 | 5.50 | 5.31 | 山道江歸，，歸去一相逢。西相知，，，何在自一寒。 |
| 500 | 4.61 | 4.62 | 南雲寒已盡，不得秋深盡。唯思如何處，難見見山風。 |
| 1000 | 4.32 | 4.50 | 野色深秋夜，遙時入雨時。誰言與高手，歸意一時愁。 |
| 2000 | 4.02 | 4.36 | 石轉三千里，山閑一四鄰。不同無有志，何用老空書。 |
| 2999 | 3.94 | 4.28 | 夜高高月裏，春色下朝煙。此去一離恨，無心正自傷。 |

（M4 Pro 單核心，每步約 0.46 秒，全程約 23 分鐘。完整紀錄在 `checkpoints/model.json` 的 `meta.history`。）

幾個值得注意的地方：

- **第 0 步的 loss 是 7.59**，和理論值 `ln(2001) = 7.60` 吻合，輸出是完全的亂碼。
- **第 100 步**，模型已經發現逗號和句號，但位置還不準。
- **第 500 步**，五個字一句、逗號句號交替的格式完全正確。格式是最容易學的規律，所以最先學會。
- **之後**，進步來自用字：詞彙搭配越來越自然，偶爾出現對仗（例如第 900 步的「白雲飛玉閣，紅葉落金林」）。
- **訓練 loss 與驗證 loss 從第 1000 步左右開始拉開。** 最後訓練 loss 3.94、驗證 loss 4.28，而且驗證 loss 在最後一千步幾乎不再下降。這是輕微的 overfitting：模型開始記住訓練集裡特定的詩句。再訓練下去，訓練 loss 會繼續降，但模型實際的能力不會再進步。要突破就得增加資料，或加入 dropout 之類的正則化。
- 驗證 loss 4.28 對應 perplexity 約 72：平均而言，模型對下一個字的把握程度，相當於在 72 個字裡面挑。


## 9. 訓練不順利時的檢查清單

依序檢查，每一項都能排除一大類問題：

1. **初始 loss 是否接近 `ln(V)`？** 不是的話，問題在初始化或 loss 的計算。
2. **能不能 overfit 一個極小的 batch？** 拿兩條序列反覆訓練，loss 應該降到接近理論下限。做不到表示 forward、backward 或更新的某一環斷了。`tests/gpt.test.ts` 有這個測試。
3. **Gradient check 是否通過？** 排除 backward 寫錯。
4. **Loss 有沒有在下降？** 完全不動通常是學習率太小，或忘了呼叫 `optimizer.step`。劇烈震盪或暴增是學習率太大。
5. **生成的樣本長什麼樣子？** 數字之外，直接看輸出最有感覺。`train.ts` 每隔一段時間就印一首詩，可以看到它從亂碼、到學會標點位置、再到出現像樣的詞彙。

## 重點回顧

- 訓練資料是文字本身，答案是輸入往後移一格。
- Cross-entropy 是「正確答案的機率」取 `−log`；剛開始應該接近 `ln(V)`。
- 每一步：歸零、forward、backward、clip、更新。
- Adam 用梯度的移動平均（動量）穩定方向，用梯度平方的移動平均為每個參數調整步伐。
- 學習率先暖身、後衰減。
- 驗證 loss 才是模型真正的能力；它和訓練 loss 拉開就是 overfitting。
