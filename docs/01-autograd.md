# 01　Autograd：讓電腦自己算微分

對應原始碼：`src/value.ts`

## 1. 問題：二十萬個旋鈕，每個該往哪邊轉？

把模型想成一台有 229,376 個旋鈕的機器。把一首詩餵進去，它會吐出一個數字 **loss**，代表「預測得有多爛」。我們的目標是把 loss 轉到最低。

對任何一個旋鈕 `w`，我們想知道的只有一件事：

> 如果把 `w` 往上轉一點點，loss 會變大還是變小？變多少？

這個「變化的比例」就是**導數**（derivative），寫成 `∂loss/∂w`。所有參數的導數合在一起，稱為**梯度**（gradient）。

知道梯度之後，更新規則很單純：

```
w ← w − 學習率 × ∂loss/∂w
```

導數是正的（往上轉會變糟）就往下轉，導數是負的就往上轉。導數的絕對值越大，表示這個旋鈕越有影響力，轉的幅度也越大。這就是**梯度下降**（gradient descent）。

所以整個訓練的關鍵只剩一個：**怎麼算出梯度？**

## 2. 笨方法：數值微分

導數的定義就是「挪動一點點，看輸出變多少」：

```
∂loss/∂w ≈ (loss(w + h) − loss(w − h)) / 2h        h 是一個很小的數，例如 0.00001
```

這個方法一定對，寫起來也只要三行。但是每算一個參數的導數，就要把整個模型跑兩遍。229,376 個參數就是將近 46 萬次 forward，才能更新**一步**。訓練需要幾千步，完全不可行。

數值微分並非沒用。它慢但可靠，正好用來檢查快的方法有沒有寫錯。這就是 gradient check，第 02 章會再談。

## 3. 聰明方法：連鎖律

任何複雜的計算，拆到最細都是加、乘、指數這類簡單運算串起來的。而每個簡單運算的導數，高中就學過了。

**連鎖律**（chain rule）說：如果 `L` 依賴 `e`、`e` 又依賴 `d`，那麼

```
∂L/∂d = ∂L/∂e × ∂e/∂d
```

白話：「`d` 對 `L` 的影響」等於「`d` 對 `e` 的影響」乘上「`e` 對 `L` 的影響」。影響力沿著計算的鏈條一路相乘。

### 手算一次

設 `L = (a·b + c)²`，其中 `a = 2`、`b = −3`、`c = 10`。把它拆成三個步驟：

```
d = a × b     →  d = −6
e = d + c     →  e = 4
L = e²        →  L = 16
```

畫成圖（這就是**計算圖**，computation graph）：

```
a ──┐
    ×──► d ──┐
b ──┘        +──► e ──► (²) ──► L
c ───────────┘
```

**Forward**（由左到右）算出每個節點的值，上面已經做完了。

**Backward**（由右到左）算出 `L` 對每個節點的導數。從終點出發，一次退一步：

| 步驟 | 局部導數 | 連鎖律 | 結果 |
|------|----------|--------|------|
| `∂L/∂L` | | 自己對自己 | **1** |
| `∂L/∂e` | `L = e²` → `2e = 8` | `1 × 8` | **8** |
| `∂L/∂d` | `e = d + c` → `1` | `8 × 1` | **8** |
| `∂L/∂c` | `e = d + c` → `1` | `8 × 1` | **8** |
| `∂L/∂a` | `d = a × b` → `b = −3` | `8 × (−3)` | **−24** |
| `∂L/∂b` | `d = a × b` → `a = 2` | `8 × 2` | **16** |

驗證一下 `∂L/∂a = −24`：把 `a` 從 2 改成 2.001，`L = (2.001 × −3 + 10)² = 3.997² = 15.976`，變化量 `−0.024`，剛好是 `0.001 × −24`。

### 兩個值得記住的規則

從上表可以歸納出兩個最常用的局部導數：

- **加法把梯度原封不動地分給兩邊。** `e = d + c`，`d` 和 `c` 各拿到完整的 8。
- **乘法把梯度乘上「對方的值」再傳過去。** `d = a × b`，`a` 拿到 `8 × b`，`b` 拿到 `8 × a`。

第一條規則之後會變得非常重要：殘差連接（第 04 章）之所以有效，正是因為加法讓梯度暢通無阻。

## 4. 為什麼一次 backward 就能拿到所有梯度

注意上表的計算順序：算 `∂L/∂a` 時用到的 8，是前面已經算好的 `∂L/∂d`。**每個節點的梯度只算一次，就被所有上游節點重複利用。**

所以不管有多少個參數，只要：

1. 跑一次 forward，記下每個中間值
2. 跑一次 backward，每個節點做一次「梯度 × 局部導數」

就能得到 loss 對**所有**參數的導數。成本大約是 forward 的兩到三倍，和參數數量無關。比起數值微分的 46 萬次 forward，這是讓深度學習成為可能的關鍵。

這個做法的正式名稱是**反向模式自動微分**（reverse-mode automatic differentiation），用在神經網路上時習慣叫**反向傳播**（backpropagation）。

> **為什麼是「反向」？** 也可以從輸入往輸出推（forward-mode），但那樣一次只能得到「所有輸出對**一個**輸入」的導數。神經網路是「幾十萬個輸入（參數）、一個輸出（loss）」，從輸出往回推，一次就拿到全部。

## 5. 把它寫成程式：`Value` 的設計

`src/value.ts` 的 `Value` class 只做三件事。

### 5.1 每個值記住自己的來歷

```typescript
class Value {
  data: number        // forward 算出的值
  grad = 0            // ∂(最終輸出)/∂(這個值)
  parents: Value[]    // 我是由誰算出來的
  backwardFn          // 怎麼把我的 grad 分給 parents
}
```

每做一次運算就產生一個新的 `Value`，並用 `parents` 指回輸入。寫 `a.mul(b).add(c).pow(2)` 的同時，計算圖就自動建好了。你不需要事先宣告圖的結構，算式怎麼寫、圖就長怎樣。這種做法稱為 **define-by-run**（動態計算圖），PyTorch 也是這樣設計的。

### 5.2 每個運算附帶自己的局部導數

```typescript
mul(other) {
  const out = new Value(this.data * other.data, [this, other])
  out.backwardFn = () => {
    this.grad  += other.data * out.grad
    other.grad += this.data  * out.grad
  }
  return out
}
```

`backwardFn` 是一個 closure，它抓住了 forward 時的輸入值（`this.data`、`other.data`），等 backward 時才執行。每個運算只需要知道**自己的**局部導數，完全不必知道整張圖長什麼樣。這就是 autograd 可以無限組合的原因：新增一種運算，只要寫好它的 forward 和局部導數即可。

### 5.3 為什麼是 `+=` 而不是 `=`

一個值可能被用到不只一次。例如 `y = a × a + a`，`a` 透過三條路徑影響 `y`。微積分的多變數連鎖律說：**總影響等於各條路徑的影響相加**。

```
y = a² + a    →   ∂y/∂a = 2a + 1
```

`a = 3` 時答案是 7：乘法那邊貢獻 `3 + 3 = 6`，加法那邊貢獻 `1`，三次 `+=` 加起來剛好是 7。如果寫成 `=`，後面的會蓋掉前面的，結果就錯了。

`+=` 也帶來一個副作用：梯度會跨訓練步驟累積。所以每一步開始前必須把梯度歸零（`optimizer.zeroGrad()`），這是初學者最常忘記的事。

### 5.4 為什麼需要拓撲排序

節點把梯度傳給 parents 之前，自己的 `grad` 必須已經**收齊**。也就是說，所有用到它的節點都得先處理完。

```
a ──► b ──► d
│           ▲
└───────────┘      （a 同時被 b 和 d 用到）
```

如果先處理 `a` 再處理 `b`，`a` 就會漏掉從 `b` 傳回來的那一份梯度。

**拓撲排序**（topological sort）正是為了解決這個問題：把圖排成一列，保證每個節點都排在它所有 parents 的後面。做法是深度優先走訪，「parents 全部排好之後，才把自己放進去」：

```typescript
const visit = (v) => {
  if (visited.has(v)) return
  visited.add(v)
  for (const p of v.parents) visit(p)
  order.push(v)          // parents 都排好了，才輪到自己
}
```

得到的 `order` 是 forward 的順序，倒過來走就是 backward 的正確順序。

## 6. 用它訓練一個神經網路

`tests/value.test.ts` 的最後一個測試，只用 `Value` 就訓練出一個會算 XOR 的小型神經網路。整個「深度學習」的流程濃縮在這幾行：

```typescript
for (let step = 0; step < 500; step++) {
  for (const p of params) p.grad = 0            // 1. 梯度歸零
  const L = /* 用 Value 運算算出 loss */          // 2. forward（同時建圖）
  L.backward()                                   // 3. backward
  for (const p of params) p.data -= 0.1 * p.grad // 4. 梯度下降
}
```

訓練 GPT 的迴圈（`src/trainer.ts`）結構和這四行完全相同，只是模型更大、更新規則更講究。

## 7. 為什麼不直接用 `Value` 寫 GPT

可以，而且數學上完全等價。問題是效率：`Value` 的每一個數字都是一個物件，帶著自己的 `parents` 陣列和 closure。

我們的模型處理一首詩，光是最後一層就要做 320 萬次乘法和加法，那就是幾百萬個 `Value` 物件。一個 batch 32 首詩，一步訓練就要配置上億個物件，速度會慢上百倍。

解法是把計算圖的節點**變粗**：一個節點裝的是一整個矩陣，一個運算是一整個矩陣乘法。圖的節點數從上億個降到幾千個，裡面的數字用緊湊的 `Float64Array` 存放。觀念一模一樣，只是局部導數從「數字對數字」變成「矩陣對矩陣」。

這就是下一章的 `Tensor`。

## 重點回顧

- 訓練需要 loss 對每個參數的導數（梯度），梯度下降沿著梯度的反方向更新參數。
- 連鎖律：影響力沿著計算鏈相乘；多條路徑的影響相加。
- 計算圖記錄「誰由誰算出來」；每個運算只需要知道自己的局部導數。
- Backward 從輸出往回走一遍，就得到所有參數的梯度，成本和一次 forward 同一個量級。
- 拓撲排序保證每個節點在往回傳之前，已經收齊所有梯度。
